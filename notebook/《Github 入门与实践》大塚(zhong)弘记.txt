1.什么是GitHub
github图表名为"octocat"，造型网址为：http://octodex.github.com
GitHub是为Git仓库提供的网络服务——GitHub上面的仓库都由git管理：http://git-scm.com
其他托管Git的软件：gitlab、gitBucket、gitorious、RhodeCode，UI不同，需要学习成本

2014，协同工作为主流，（2021开始则以AI协作为主流）
群件(Groupware)和CRM (Customer Relationship Management顾客关系管理)  脱颖而出
Github的Pull Request请求合并，对比合并前后差异、评价，不必再在版本管理、BUG跟踪、代码审查、邮件、IRC等多工具组合上花大量心思，象征着社会化编程
             issue实现任务管理、BUG报告、TiDD(Ticket-driven Development)  ，采用@name @gtoup/team #number 的格式。
             输入的语法格式统一为GFM(GitHub Flavored Markdown)，实现wiki功能
             开发模式与开源软件相同，不必额外学习专用软件的开发过程
             Gist管理零散代码，Star收藏，Broadcast官方通知，Bolg官方博客，Repositories贡献仓库，contributors贡献名单，Pulse访问热度，Network仓库状态和成员信息表，release历史版本，
             查看代码：blame按行，raw在浏览器看，查看最近7天http://.../master@{7.day.ago}...master    day可替换为week/month/year
                              查看指定日期http://.../master@{2013-01-01}...master

4.管理命令
4.1对文件
git init 初始化，生成的.git称为"工作树"，管理文件快照
git status   显示文件更改状态
git add
git commit
git log 查看提交日志
git push 推送更新



git commit 自动打开编辑器，不编辑则关闭后中止提交
git commit - m ".."单行(不打开编辑)
                  --amend 修改提交内容
                  -a 相当于执行git add

git log - p md 显示md文件提交前后的内容变化
            --graph 以图表形式给出
git diff 工作树的差别，默认与最新一次提交的区别， HEAD 与暂存区差别，

git reflog 仓库的操作日志

git reset --head回滚版本

git rebase -i 覆盖提交历史

--------------
git rebase -i HEAD~2
->显示内容
pick 7aaaa m1
pick 6bbbb m2

将m2压缩到m1，改为如下
pick 7aaaa m1
fixup 6bbbb m2

再次查看m2的哈希值会发现从6bbbb改为7aaaa，6bbbb记录则彻底销毁

6.Flow替代Fork
以部署为中心，流程自动化，
令master分支保持可部署状态，只为特定作业创建分支，更加简单，所以可实现快速

短时间内部署多次，HEAD无法返回太久之前的提交
解决代码问题后尽量快部署，不要等反馈太多再搞，避免Pull Request太大，审阅容易出漏洞


6.2以发布为中心
书本推荐了git-flow工具帮助自动化，建议绘制开发流程图，分支为一条条线，版本为圆点，合并则线段连接两条线
